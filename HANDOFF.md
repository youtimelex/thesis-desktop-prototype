# Thesis — комплект передачи разработки

Актуально на **17 ноября 2026 года**.

Это точка входа в материалы для команды, которая переносит интерфейс и поведение
десктопного Thesis в свой клиентский проект. **Первый этап выполняется на демоданных;
реальные интеграции запланированы отдельно.** Комплект объясняет продукт, устройство текущего прототипа,
переходы между экранами, состояние данных и нюансы сценариев. Он предназначен
для чтения вместе с исходниками и работающим прототипом.

**Посмотреть:** [опубликованный прототип на Layero](https://thesis-desktop-demo.layero.app/?preview=1).
Ранее опубликованная [версия на Vercel](https://thesis-desktop-demo.vercel.app/?preview=1)
сохранена отдельно и не включает последнюю правку меню пространства.
**Запустить:** в существующей рабочей копии — `npm run dev` из корня проекта, затем
<http://127.0.0.1:4192/?preview=1>.
На новой машине сначала подготовьте Node.js 24 и выполните `npm ci` из корня
распакованного проекта. [Подробности запуска](docs/development/04-development-delivery.md).

## Что команда должна сделать первым

**Цель первого этапа:** воспроизвести интерфейс, навигацию и наблюдаемое
поведение описанных экранов на переданных демоданных. В объём входят состояния
материалов, формы и проверки ввода, ошибки и повторы, локальные черновики,
источники и история Ассистента, адаптация окна и работа с клавиатурой.
Поведение браузерного экспорта, копирования и передачи резюме также входит
в референс. Для выбранной командой платформы способ вызова системных функций
может потребовать отдельного согласования.

Подключение Thesis API, настоящий SSO, запись аудио, загрузка исходных медиа,
агент ВКС, распознавание, LLM, серверные права и синхронизация относятся к
следующему этапу. На первом этапе их состояния воспроизводятся демонстрационным
слоем. Точные проценты и секунды демотаймеров не являются требованиями к будущим
сервисам. Нативная оболочка и технология целевого проекта этим выбором не заданы.

**Стартовая задача:** перенести в целевой клиентский проект команды сценарий
«Все записи → поиск → запись → материалы → другая запись → возврат» на
демоданных. Сначала сохраняются контекст, фильтры, фокус и правила панелей;
затем расширяется покрытие остальных экранов. Контрольный пример и критерии
готовности приведены в [приёмке первого этапа](docs/development/05-stage-one-acceptance.md).

Результат задачи — запускаемая версия с исходниками и инструкцией, по которой
другой разработчик повторит этот сценарий и увидит те же результаты. К ней
прилагаются результаты затронутых проверок и перечень известных отклонений.
Даты и исполнители назначаются командой отдельно.

## Что за продукт

Thesis — рабочее место для записей встреч и их материалов. Пользователь получает
запись с диктофона, импортирует файл или подключает агента к конференции, затем
находит её в библиотеке, читает резюме и транскрипцию, работает со спикерами и
задаёт вопросы Ассистенту. Записи располагаются в личном или общем пространстве,
при необходимости — в папке. Пространство определяет контекст размещения и
обсуждаемую аудиторию, а выбранные источники Ассистента определяют материалы
конкретного диалога.

Десктопный сценарий: одна рабочая область, глобальная
навигация, открытая запись, необязательные список и свойства, общий плеер.
Рабочих вкладок для нескольких открытых записей нет. Внутри записи остаются
переключатели «Обзор», «Транскрипция», «Ассистент». Рамка macOS имитируется в
браузере.

## Первый проход по прототипу

Используйте ссылку с `?preview=1`: данные модели в таком режиме остаются в памяти
и сбрасываются при перезагрузке. Не оценивайте сохранение между перезагрузками
по этому режиму; обычное хранение отдельно описано в главе 2.

| Пример | Что сделать | Что должно получиться |
| --- | --- | --- |
| Возврат из поиска | В «Все записи» введите `комитет`, откройте «Проектный комитет» и нажмите «Назад» | Запрос `комитет` сохраняется, фокус возвращается к исходной строке |
| Переключение записи | В отдельном поиске найдите «Проектный комитет», откройте запись и в панели «Записи» выберите «Оперативное совещание» | «Назад» возвращает в прежний поиск с прежним запросом |
| Прямая ссылка | Откройте в новой странице `?preview=1#/records/project-committee/summary` | Материалы открываются, кнопка «Записи» не предлагает выдуманную исходную подборку |
| Пространства | В каталоге сравните счётчики со строками боковой панели | «Личное» — 5, «Проектный комитет» — 6, «Пилот с заказчиком» — 4; это записи, без черновиков |
| Узкое окно | При ширине 900px откройте список внутри записи, сфокусируйте кнопку закрытия и нажмите Escape | Список закрывается, фокус возвращается к «Записи» |
| Источники Ассистента | В демодиалоге `dialog-draft` выберите только «Проектный комитет» и отправьте готовый вопрос | После первого вопроса источники доступны для просмотра, изменение требует нового диалога |

Подробные шаги, ссылки, соответствующие тесты и ограничения проверки — в главе 5.
Полные предусловия, последствия и исключения всех сценариев — в главе 3.

## Что считать реализацией, а что требует решения

Документы используют три разных вида утверждений:

- **Текущее поведение** — то, что реализовано в переданных исходниках.
  Ссылки ведут на соответствующие модули, функции и тесты.
- **Сохраняемое правило** — продуктовая договорённость, которую нужно учитывать
  при переносе поведения в реальный клиент. Например, пустой выбор источников
  не должен расширяться автоматически.
- **Требует согласования** — вопрос для реализации или приёмки: серверные
  права, API, реальные медиа, синхронизация, нативная оболочка либо конкретное
  правило интерфейса, ещё ожидающее подтверждения.

Существующий React-код — исполняемый референс сценариев. Это не готовая
производственная архитектура и не спецификация серверного API. Здесь нет
подключённого Thesis backend, настоящей авторизации, захвата звука, распознавания
или модели ИИ. При этом экспорт текстовых материалов, буфер обмена и некоторые
браузерные действия действительно выполняются — детали описаны отдельно.

## Правила, важные для переноса

| Правило | Почему его легко потерять |
| --- | --- |
| Возврат из записи сохраняет исходный список, фильтры, поиск, прокрутку и выбранную запись | URL записи не содержит всего состояния пользователя |
| Список рядом с записью и список возврата имеют разное назначение | Текущая боковая панель показывает каталог области, а не обязательно поисковую выборку |
| Прямая ссылка и перезагрузка не восстанавливают вымышленную подборку | Надёжный контекст списка существует только после соответствующего перехода |
| Источник записи, пространство, папка, аудитория и источники Ассистента — разные понятия | Смена одного не должна неявно подменять другое |
| Перемещение меняет размещение одной записи; переход между пространствами требует подтверждения последствий для доступа | Копия не создаётся, прежняя папка сбрасывается |
| Удаление папки сохраняет записи и черновики | Нужно снять назначение папки, а не удалить её содержимое |
| Несколько черновиков независимы | Продолжение и завершение одного не должны затрагивать остальные |
| Предыдущие материалы остаются читаемыми во время повторной обработки | Доступность материала и стадия задачи — разные состояния |
| Каждый вопрос Ассистента получает снимок источников | Повтор не должен незаметно использовать изменившийся текст или расширенный набор |
| История и встроенный Ассистент используют объекты диалогов по правилам контекста | Простого совпадения одного источника недостаточно для миграции старого диалога |
| Недоступный использованный источник скрывает соответствующий ответ | Прототип демонстрирует правило, но настоящий контроль доступа должен выполнять сервер |
| Демосписок участников не меняет права и не отправляет приглашения | Визуальное редактирование списка не является реализацией членства |

Вопросы по точкам входа перечислены в
[реестре решений первого этапа](docs/development/05-stage-one-acceptance.md).
У каждого указан текущий результат и необходимое подтверждение до приёмки.
Эти вопросы не блокируют стартовый сценарий библиотеки. Поведение нескольких
диалогов записи описано в главе 3.
