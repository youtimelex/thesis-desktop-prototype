## 1. Локальный запуск

Корень текущего рабочего каталога:
`/Users/aleksandrcagan/thesis/mvp0-desktop-vini-focus-preview`.
После передачи архива путь может быть другим; команды выполняются из корня
распакованного проекта, где находятся `package.json`, `index.html` и `src/`.

В рабочей копии зависимости уже установлены. На новой машине установите
совместимый Node.js и выполните `npm ci` по переданному lockfile. Для повторения
этого среза подходит Node.js 24; установленный Vite требует
`^20.19.0 || >=22.12.0`. Сам проект не задаёт `engines` в `package.json`.

```sh
npm run dev
```

Сервер слушает только `127.0.0.1:4192`, `strictPort: true`. Откройте
<http://127.0.0.1:4192/?preview=1>. Если порт занят, сначала выясните, не запущен
ли уже этот проект. Не останавливайте чужой процесс и не меняйте порт ради
проверки. Команда `npm run preview` служит для просмотра готового `dist` на том
же порту; её не следует запускать одновременно с dev-сервером.

Сборка:

```sh
npm run build
```

Это `tsc --noEmit` и `vite build`; результат — `dist/`. Настройки:
[package.json](../../package.json), [tsconfig.json](../../tsconfig.json),
[vite.config.ts](../../vite.config.ts).

`index.html` — браузерная рамка приложения с имитацией macOS. Высоту корневой
области синхронизирует `ResizeObserver`; служебная шапка и кнопка «Без рамки»
удалены. Нативное окно, системная навигация и Electron/Tauri здесь не реализованы.

## 2. Как подключён VINi

Текущий набор: `@vini-ds/ui`, `@vini-ds/tokens`, `@vini-ds/agent` версии
`0.1.0-alpha.14`. Это точные версии этого среза, а не обещание последней версии
в реестре. Не обновляйте их в рамках обычного знакомства с проектом.

### Провайдеры и стили

В [main.tsx](../../src/main.tsx) импортируются шрифты, темы и типографика VINi,
семантические алиасы продукта, общие стили, затем стили UI и продуктовой
компоновки. Порядок имеет значение для приоритета применяемых правил.
`AppearanceProvider` использует `ThemeBrandProvider` с
`brand="vini"` и `typographyScope="desktop"`.

| Уровень | Где искать | За что отвечает |
| --- | --- | --- |
| Компоненты и их состояния | `@vini-ds/ui` | Кнопки, поля, меню, диалоги, панели, вкладки, карточки и прочие публичные компоненты |
| Значения дизайн-системы | `@vini-ds/tokens` | Цвета, размеры, шрифты, типографика, темы |
| Продуктовые алиасы | [tokens.css](../../src/tokens.css) | Связь имён Thesis с токенами VINi и отдельные параметры раскладки |
| Общие адаптеры | [ui.tsx](../../src/ui.tsx) | `Button`, `IconButton`, `Modal`, `Field`, `AreaPicker`, `Empty` и другие композиции для Thesis |
| Оболочка и адаптация | [dashboard-shell.css](../../src/dashboard-shell.css), [focus-shell.css](../../src/focus-shell.css) | Рабочая область, панели, контейнеры, доступная ширина |
| Экранные композиции | [vini-layout.css](../../src/vini-layout.css), остальные CSS в `src/` | Раскладка экранов и локальные композиции |
| Оформление | [appearance.tsx](../../src/appearance.tsx) | Light/Dark, цветовая схема, локальная настройка языка |

Изображения значков берутся из Material Symbols Rounded, поставляемого VINi;
`Icon` подставляет поддерживаемую лигатуру. Первое открытие может на короткое
время показывать текстовое имя значка, пока шрифт не загрузился. В проверке
публикации нужно дождаться загрузки шрифтов и проверить фактические значки.
Наличие зависимости Phosphor в `package.json` не означает, что текущий `Icon`
рисует значки через неё.

### Сохраняемые визуальные решения

- Основной акцент — синий, действие записи — красное; предупреждения, успех и
  ошибки используют свои семантические цвета. Доступны светлая и тёмная темы.
- Настройки используют штатную композицию Card VINi.
- Информационное сообщение в списке записи сохраняет согласованный синий вид
  с локальными стилями. Это известное продуктовое исключение, а не штатный
  нейтральный Alert VINi.
- Каталог пространств использует `list_alt`, общие пространства — `sensor_door`,
  личное — `person`. Счётчик и меню пространства остаются отдельными элементами.
- Фокус поиска восстанавливается действиями приложения. Заметность штатной
  рамки InputGroup остаётся вопросом к дизайн-системе; локальную подмену
  внутреннего оформления поля не считать принятой реализацией.

Этот комплект не утверждает полного соответствия VINi или завершённого аудита
доступности. При изменении оформления проверяйте реально применяемые правила
и их приоритет, а не только имя класса.

### MCP и перенос на другое рабочее место

В рабочей копии `.codex/config.toml` запускает `.vini-ds/npm-launcher.mjs`
через абсолютный локальный путь. Само наличие файла не подтверждает
подключение текущего чата. Прочитайте `vini://runtime/connection` в используемом
клиенте: корень должен указывать на этот проект, версия — на установленный набор.
Запрос через VINi local с явным `appRoot` проверяет выбранный каталог, но не
переключает постоянное соединение другого чата.

В архиве сохранён проектный запускатель `.vini-ds/npm-launcher.mjs` вместе с
квитанцией установки и `QUICKSTART.md`. Сам запускатель разрешает пакеты
относительно своего каталога. В квитанции есть абсолютный путь машины автора;
для активной конфигурации нужен путь вашего рабочего места. Запись MCP должна
ссылаться на фактический путь распакованного проекта:

```toml
[mcp_servers.vini-ds]
command = "node"
args = ["<абсолютный путь проекта>/.vini-ds/npm-launcher.mjs"]
enabled = true
startup_timeout_sec = 10
```

Это шаблон настройки, а не команда автоматической замены глобального MCP.
После установки зависимостей и настройки проверьте соединение в выбранном
клиенте отдельно от сборки интерфейса.

Для интерфейсной работы используйте проектную инструкцию
[VINi](../../.agents/skills/vini-ds/SKILL.md), публичные контракты компонентов и
токены установленной версии. Продуктовая раскладка и бизнес-поведение принадлежат
Thesis; внутренние состояния компонентов — VINi. Обновление пакетов, проверка
запущенной страницы и проверка MCP-соединения — три самостоятельные проверки.
Перенос абсолютного пути с машины автора не является настройкой нового клиента.

## 3. Хранилище во время проверки

Обычный режим сохраняет модель и часть настроек в хранилище браузера.
`?preview=1` создаёт модель из демоданных в памяти и не сохраняет её изменения;
при перезагрузке сценарий начинается заново. Тема может первоначально
считываться из прежнего локального значения, но её изменения в preview не
записываются. Полный перечень ключей и восстановление состояния —
в [главе 2](02-architecture-data.md).

Постоянные данные зависят от origin: локальный 4192 и опубликованный домен имеют
разные хранилища. Повторная публикация на том же домене не очищает прежние
значения и не является миграцией. Режим `?preview=1` нужен для повторяемого
просмотра и безопасной проверки; он не предназначен для теста долговременного
сохранения. Для последнего используйте отдельный тестовый профиль/контекст.

Скрытое демонстрационное состояние сети может сохраниться как `offline` в
обычном режиме. Переключатель сети удалён по согласованию, само значение
оставлено. Блокировки в таком случае не означают, что приложение проверило
соединение ОС. Не сбрасывайте хранилище пользователя ради «исправления» демо.

## 4. Какие проверки запускать

### Модель

```sh
npm test
```

Команда запускает именно `tests/model.test.ts`. Другие `*.test.ts` в `tests/`
не включаются автоматически: среди них есть отдельные тесты экспорта, истории
записи, владельца, переименования и сессии рабочего контекста. При изменении
соответствующего модуля изучите их импорты и запустите нужный файл через
`node --experimental-strip-types --test tests/имя.test.ts`.

### Браузерные сценарии

Для следующих конфигураций сначала должен работать сервер 4192. Они не
запускают сервер сами, используют отдельные браузерные контексты; сценарии
открывают страницу с `?preview=1`.

| Конфигурация в `tests/` | Что проверяется |
| --- | --- |
| [focus-navigation.config.ts](../../tests/focus-navigation.config.ts) | Маршруты и возвраты, поиск, сохранение контекста, панели записи, фокус, системный share и fallback |
| [adaptive-window.config.ts](../../tests/adaptive-window.config.ts) | Доступная ширина, подсказки Ассистента, компактная навигация и фокус в обеих темах |
| [assistant-source-lock.config.ts](../../tests/assistant-source-lock.config.ts) | Выбор источников до первого вопроса, чтение источников после него |
| [sidebar-counts.config.ts](../../tests/sidebar-counts.config.ts) | Согласованность счётчиков, доступность меню, компактный режим и отсутствие hover |
| [import-validation.config.ts](../../tests/import-validation.config.ts) | Невалидный файл не оставляет предыдущий выбор доступным к отправке, восстановление валидным выбором |
| [workspace-accessibility.config.ts](../../tests/workspace-accessibility.config.ts) | Доступные сведения в компактных строках пространств |
| [empty-focus.config.ts](../../tests/empty-focus.config.ts) | Восстановление фокуса в пустых результатах |
| [menu-radio.config.ts](../../tests/menu-radio.config.ts) | Меню выбора и состояния radio-пунктов |
| [login-vini.config.ts](../../tests/login-vini.config.ts) | Ввод адреса, демовход через SSO, справка, подтверждение смены сервера и фокус в обеих темах |

Пример:

```sh
npx --no-install playwright test -c tests/focus-navigation.config.ts
```

Не используйте `npm run test:browser` как «все актуальные тесты»: команда без
`-c` берёт корневой `playwright.config.ts` с `overview.spec.ts`, который не входит
в приёмочный набор выше. Для приёмки запускайте явную конфигурацию из таблицы.
Перед любым дополнительным набором проверьте `baseURL`, `webServer` и
`testMatch`: целевой адрес этого проекта — `127.0.0.1:4192`.

### Минимальная приёмка изменения

Для UI или поведения: сборка, затронутые модельные тесты, соответствующий набор
выше и проверка в браузере. Для навигации отдельно проверить: прямую ссылку,
перезагрузку, вход из списка/поиска/диалога/главной, возврат и фокус. Для
материалов — предыдущую версию при обработке, ошибку нужной фазы, повтор и
недоступный источник. Для layout — обе темы, широкое и узкое окно, клавиатуру.
Документационные правки проверяются ссылками и соответствием коду; они не
требуют нового полного UI-аудита.

Последняя поставка: 16 ноября сборка прошла, Vercel вернул `READY`, в браузере
проверены загрузка приложения и шрифтов без служебной шапки, переход в
пространства. Полная матрица сценариев в опубликованной среде в эту проверку
не входила. Указанные выше наборы — исполняемые проверки, а не утверждение,
что все они были повторно запущены при подготовке документации.

## 7. Последующий этап: реальные интеграции

Эти работы не входят в согласованный первый этап переноса интерфейса и
поведения. До их оценки нужно отдельно определить контракт и объём конкретного
интеграционного сценария. Демослой первого этапа не подтверждает эти решения.

| Область | Как сейчас | Что нужно решить/реализовать |
| --- | --- | --- |
| Оболочка клиента | React DOM и браузерная рамка | Целевая платформа, нативное окно, жизненный цикл, дистрибуция и обновления |
| Сервер и SSO | Локальная валидация адреса, задержка и `authenticated` | Discovery, настоящий вход, токены/сессии, ошибки, смена сервера |
| Доступ к материалам | Клиентские функции и флаги фикстур | Серверный ACL, экспорт, отзыв доступа, правила распространения материалов |
| Запись и локальные файлы | Счётчики времени и объекты модели | Аудиоустройство, разрешения, реальные файлы, безопасное хранилище, пауза и восстановление |
| Загрузка и обработка | `tick` изменяет локальное состояние | API задач, прогресс, очередь, идемпотентность, прерывание и повтор по фазам |
| Ассистент | Локальный ответ по снимкам строк | Схема запросов, версии источников, ограничения контекста, отмена, ссылки на подтверждённые источники |
| Синхронизация | `localStorage`, один фиксированный владелец | Разделение аккаунтов, миграции, конфликт изменений, удаление/retention и офлайн-режим |
| Членство | Демосписок и неотправленные черновики | Приглашения, доставка, роли, разрешения и серверные состояния |
| Системные функции | Браузерный share/clipboard/печать и демоплеер | Адаптеры выбранной десктопной платформы и проверенные fallback-сценарии |

Эта таблица — границы следующей реализации. Из неё нельзя выводить уже выбранные
backend endpoints, технологию нативной оболочки или обещания приватности.
